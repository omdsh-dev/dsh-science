# Agent Note: Science Runtime and the local Conda provider

Status: proposed

English | [中文](2026-08-13-science-runtime-and-local-conda-provider.zh.md)

## Problem

The [Science Mode MVP record](../feature/2026-08-12-science-mode-core-mvp.md) freezes durable Science Session facts and stages Conda-prefix Runtime work as Phase 2, but it does not yet define the executable boundary closely enough to implement safely. A naive provider could duplicate process-group cleanup already owned by `ctx.subprocess`, inherit ambient credentials despite promising a clean environment, authorize the project directory instead of Science scratch, append a run after spawning it, or combine host paths with a remote execution world.

The boundary also has to keep the Session log authoritative. Environment identity, run start, and terminal settlement are durable facts; mutable process handles and scratch files are not. Later model-facing tools need one operation that makes each external fact and commits its event in the correct order, rather than receiving a low-level provider and becoming a second mutation authority.

Phase 2 is still pre-product infrastructure. There is no Science preset, tool, prompt, chart or Outcome consumer, client UI, persistent kernel, environment manager, or shipped bundle composition in this phase. Fake-prefix CI and opt-in real-machine acceptance prove different evidence layers and must remain separately reported.

## Proposal

### Phase boundary and package roles

Phase 2 adds one package and no production Consumer.

| Package | Owns | Does not own |
|---|---|---|
| `@deepseek-ai/dsh-science-runtime` | `ctx.scienceRuntime`, the operation/result/error vocabulary, and the sole local Conda implementation: allowlisted profile configuration, stable observation, exact-Session reservations, Science scratch, direct argv construction, timeout/result classification, and orchestration over shared services | A second execution provider, shell parsing, OS tree signalling, generic sandbox policy, tools, prompt text, presentation, UI, attachment/chart publication, or environment creation |
| Existing capability owners | `ctx.subprocess` owns managed trees, collection, TERM-to-KILL and quiescence; `ctx.sandbox` owns argv confinement and runner diagnostics; `dsh-home-paths` owns Harness-home resolution; `dsh-timeout` owns linked deadlines | Science transitions or Session mutation |

A capability with one conceivable provider and no production Consumer stays one package until a second provider appears or a production Consumer would otherwise import local-only types ([capability-seam roles](../../implemented/architecture/2026-06-13-capability-seams.md)). Phase 2 therefore does not create `@deepseek-ai/dsh-science-runtime-local` and does not claim a complete three-role seam. The exported service types stay free of Host scratch paths, Conda prefix types, and other local-only modules so a later extract does not rewrite callers.

Phase 3 adds `@deepseek-ai/dsh-tool-science` as the production Consumer. Those tools inject `ctx.scienceRuntime` and never append `science/environment-bound`, `science/run-started`, or `science/run-finished` themselves. If the folded package cannot keep local-only types off that export, Phase 3 extracts the local provider in the same change. A Loader test may assemble the folded package; it does not complete the seam and does not justify a role split. Phase 2 does not register the package in a shipped profile.

Science execution is distinct from `ctx.codeRuntime`. It runs an exact Python or R source file in a fresh process, exposes no host binding bridge or Code Mode SDK, and does not implement the deferred CPython backend recorded by Code Mode.

The local provider uses `node:fs` only for its private Host scratch after proving a host-local subprocess world. It does not route scratch through `ctx.fs`, whose current execution-world text API has no private-directory mode, exclusive marker, file-sync, or directory-sync primitive. This narrow ownership does not create a second general filesystem provider. Phase 2 also uses neither `dsh-shell` nor `ctx.jobs`: argv remains structured, and every operation is a caller-owned foreground handle rather than cross-turn background work.

### Required generic capability extensions

Phase 2 first closes four narrow generic gaps instead of bypassing the existing seams.

1. `SubprocessSpawnSpec` gains a required `environmentBase: 'scrubbed-parent' | 'empty'` field. Every current Consumer states its existing `'scrubbed-parent'` choice explicitly; Science uses `'empty'`. Local and E2B providers must give the requested program that exact base before applying `spec.env`. Provider control processes may retain their documented transport environment, but it may not become the target program's environment.
2. `SubprocessRuntime` exposes a readonly `executionWorld: 'host-local' | 'remote'` capability fact. `dsh-subprocess-local` reports `'host-local'` and E2B subprocess reports `'remote'`. The local Science provider requires `'host-local'` before it creates an owner record, directory, or Session event. `SandboxProvider` does not gain a duplicate fact: its existing Service Definition is already the same-host-kernel, host-path confinement seam, and the local provider depends on that contract. The subprocess descriptor prevents this host-path Consumer from being combined with a remote process world; it is not a general identity protocol for arbitrary remote provider pairs.
3. Runner-spawn, runner-fatal, and denial classification move from the Bash and Pwsh Consumers into an exported `dsh-sandbox` classification module. Bash, Pwsh, and Science call that one implementation. The two shell Consumers already keep a call-for-call mirror; migrating only Bash would recreate the drift that copy exists to prevent. Runner failure outranks denial because it proves the requested interpreter never ran; neither may be reported as an ordinary Python/R exception.
4. `SubprocessOutputRead` gains `utf8Validity: 'valid' | 'invalid' | 'unknown'` for the exact byte slice represented by that read. Any provider that retains those bytes computes `valid` or `invalid` from the slice before replacement decoding. That includes the local collector and E2B after it recovers the original command bytes from its base64 transport. A provider reports `unknown` only when it has already-decoded text and no recoverable byte slice. Existing text Consumers retain their current behavior. Science version and UTF-8 probes require a lossless read from offset zero with `utf8Validity === 'valid'`; they never infer validity from the absence of U+FFFD.

The Science provider consumes only the public `SubprocessHandle` verbs. It installs no process-level exit listener, sends no process-group signal directly, and does not duplicate output collectors. Those mechanics remain governed by the [subprocess seam](../../implemented/architecture/2026-07-26-subprocess-seam.md) and its synchronous-exit fallback.

### Runtime contract

The Service Definition exposes two asynchronous operations and one live result handle. Every tool-reachable operation requires a caller-owned `AbortSignal` from its first version.

| API | Contract |
|---|---|
| `bindEnvironment({ session, profileId, signal })` | Validate one configured local profile, append exactly one whole `science/environment-bound` revision, and resolve with the accepted durable value |
| `startRun({ session, language, code, toolCallId, requestHeaderSeq, signal })` | Reserve the exact live Session, revalidate its applied binding, prepare and publish a run start, then resolve with a handle; failures before publication reject without a run event |
| `ScienceRunHandle` | Exposes only `runId`, `done: Promise<ScienceRunResult>`, and idempotent `cancel(): void`; it never exposes PID, `SubprocessHandle`, executable path, or Host scratch path |
| `ScienceRunResult` | Resolves with the committed `ScienceRunTerminal` plus bounded stdout/stderr tails, exact byte totals, and truncation flags; ordinary program, timeout, and cancellation outcomes are values |

`bindEnvironment` and pre-publication `startRun` failures reject as `ScienceRuntimeError`. Misuse and capability codes are `SESSION_NOT_LIVE`, `SERVICE_DISPOSING`, `RUNTIME_BUSY`, `ENVIRONMENT_NOT_READY`, `CONFINEMENT_UNAVAILABLE`, and `INVALID_REQUEST`; caller abort, pre-publication deadline, and provider failure use `OPERATION_CANCELLED`, `OPERATION_TIMED_OUT`, and `INFRASTRUCTURE_FAILURE`. They append no run event. After `science/run-started` commits, spawn, runner, process, timeout, and caller-cancellation outcomes settle `done` as a terminal value and append `science/run-finished`. Durable non-success codes are `SPAWN_FAILED`, `SANDBOX_RUNNER_FAILED`, `SANDBOX_DENIED`, `DESCENDANT_CLEANUP_REQUIRED`, `PROCESS_SIGNALLED`, `PROCESS_EXIT_NONZERO`, `TIMEOUT`, and `CANCELLED`. A failure to prove whole-tree quiescence rejects `done` with `QUIESCENCE_UNPROVEN`. A failure to append the terminal fact to the still-live exact Session rejects with `TERMINAL_COMMIT_FAILED`. If the exact Session has already detached or been replaced, `done` rejects with `SESSION_NOT_LIVE` after quiescence; that is the only post-publication use of `SESSION_NOT_LIVE`, and it is not `TERMINAL_COMMIT_FAILED`. The runtime never appends to the detached object or a same-ID successor, and it must not return a value that looks durably committed.

`startRun` allocates its deferred `ScienceRunHandle` before publication but does not expose it until `science/run-started` has committed. It then starts runtime-owned settlement and resolves the operation with that same handle. A synchronous spawn throw or an already-rejected process promise may settle `done` before the caller observes the handle, but `startRun` still resolves the handle because the durable start already exists. The settlement task retains the exact-Session reservation until terminal commit or explicit infrastructure rejection. A quiescence failure additionally retains the Session-ID quarantine until later cleanup proves the tree dead. The local provider declares required Cordis injections for `sessions`, `subprocess`, and `sandbox`, so their services remain available through terminal settlement and provider disposal.

The request cannot choose a prefix, executable, run ID, directory, environment entry, output cap, grace period, or timeout. Source is a non-empty, well-formed Unicode string with no U+0000; its unchanged UTF-8 encoding is at most 262,144 bytes. The provider adds no BOM, newline, or normalization. It generates a UUID-form `ScienceRunId`. `codeSha256` is SHA-256 of the exact bytes flushed to the source file. `scratchKey` is `lowerhex(SHA-256(UTF-8("dsh-science-scratch-v1\0" + language + "\0") || codeBytes))`.

The local provider has one strict Cordis configuration: optional `dshHome`, required `profiles`, and optional `timeoutMs`. `profiles` is a non-empty record keyed by valid `ScienceEnvironmentProfileId`; each value declares at least one absolute `pythonPrefix` or `rPrefix` and has no unknown keys. `timeoutMs` defaults to 120,000 and accepts only safe integers from 1 through 600,000. The 262,144-byte source limit, 64,000-byte per-stream retention, and 3,000-ms termination grace are fixed protocol and safety bounds, not per-call or model-selected tuning.

### Exact-Session ownership and mutation order

Mutable operation ownership has two coordinated levels. A `WeakMap` keys controllers and handles by the exact `Session` object, while a provider-private map keys one lifecycle quarantine by Session ID and its derived Session key. Binding and run setup share one non-queuing reservation. A second operation on the same exact Session returns `RUNTIME_BUSY` before creating a run directory or event; different Session IDs may proceed concurrently. If an old lifecycle detaches, its ID quarantine remains until every owned probe and process tree is quiescent and all cleanup has settled. A same-ID successor therefore returns `RUNTIME_BUSY` before touching the shared scratch root and may reuse it only after that quarantine releases. Every append also rechecks `ctx.sessions.get(session.id) === session` so an old lifecycle can never write into a same-ID successor.

`bindEnvironment` performs this transaction:

1. Prove the exact Session is live, Science-bound, and not already running; reserve it.
2. Resolve the allowlisted profile and its static paths without creating scratch. Reject a canonical Science Session root that equals, contains, or is contained by a generic platform temp root; this keeps owned scratch visible through the Linux mount profile and prevents the sandbox's broad temp grant from subsuming it. Derive the future run policy's canonical writable roots and reject a prefix that overlaps any of them.
3. For every executable that needs a version or UTF-8 probe, plan a unique provider-owned observation directory under the Science Session root. Use that directory as the `workspaceRoot` of a `workspace-write` probe policy, derive every canonical writable root of that policy, and reject a canonical prefix that equals, contains, or is contained by any of them. Only then create or verify the owner marker and Session root, create the private observation directory, wrap the direct argv, and require `enforcement === 'full'` before spawning. Probe `HOME`, `TMPDIR`, and cwd remain inside that sandbox-visible directory. Because R chooses its per-session temporary directory before interpreter startup and requires the selected path to contain no spaces, an R observation whose canonical `tmp/` path contains an ASCII space rejects with `CONFINEMENT_UNAVAILABLE` before spawn. Wait for the whole probe tree to settle and remove the unpublished observation directory before accepting the observation. Cleanup failure is `INFRASTRUCTURE_FAILURE`. An unavailable, partial, or prefix-overlapping boundary rejects with `CONFINEMENT_UNAVAILABLE` and appends no environment event; a statically missing or unusable interpreter needs no process and may still produce an honest `invalid` observation.
4. Build one complete environment revision. All declared interpreters available means `applied`; a missing or unusable environment observation becomes an honest `invalid` value with only the facts reached and a bounded reason. Provider I/O, cancellation, timeout, and confinement failures reject instead of manufacturing an environment fact.
5. Recheck exact liveness, caller cancellation, and deadline, append `science/environment-bound`, then release the reservation in `finally`.

Explicit binding after any run is rejected rather than appending a replacement `applied` environment. Run preflight re-observes the selected binding. An identical observation appends nothing; an invalid or changed observation appends one consecutive `invalid` or `drifted` environment revision and rejects the run before a run directory or start event.

`startRun` performs this transaction:

1. Reserve the exact live Session and strictly replay its already-admitted Science events. Require the latest environment to be `applied` and the requested language binding to be `available`.
2. Re-observe that exact binding. Drift follows the environment path above and prevents execution.
3. Generate the run ID and planned private paths, derive the source hashes, and construct the fixed interpreter argv, clean environment, and `stdio` policy without creating the run directory. Stdin is always `'ignore'` (`/dev/null` locally); stdout and stderr use separate bounded collectors.
4. Derive the canonical writable roots of the fixed Science `workspace-write` policy. Reject when the canonical Conda prefix equals, contains, or is contained by any writable root; otherwise user code could mutate the environment even under full enforcement. Ask `ctx.sandbox` to confine the planned argv and require `enforcement === 'full'`. A known unavailable, partial, or overlapping boundary rejects before creating run files or publishing the start. The wrap may probe a runner but does not execute the requested source.
5. Create the private run directory, write the exact source with mode `0600`, flush the file, allocate the deferred handle, and recheck exact liveness, caller cancellation, and deadline. Append `science/run-started`; only after it succeeds expose the handle. Recheck the first-cause controller immediately before `ctx.subprocess.spawn`: a cause already latched after publication skips spawn and settles the run as `cancelled` or `timed-out`. A rejected pre-start append removes the unpublished run directory. A synchronous or asynchronous spawn failure after this point is a terminal failed run, not an abandoned start.
6. A runtime-owned background task retains the reservation while it awaits direct-process settlement, allows descendants at most the configured 3,000 ms grace to exit, then calls the sole `terminate()` verb if the tree remains live and awaits `waitForExit()` for the entire managed tree. It classifies the first owned cause, reads both collected tails from offset zero, appends the complete terminal event, and only then releases the Session reservation. A tree that needed post-parent termination cannot be reported as `success`.

Terminal classification first uses the earliest latched owned cause: a deadline becomes `timed-out`, while caller signal, `cancel()`, or normal service disposal becomes `cancelled`. If no owned cause was latched, sandbox runner failure outranks sandbox denial, then spawn failure, forced descendant cleanup, signal death, and nonzero exit become `failed`; exit zero becomes `success`. Safe failure codes are durable, while raw errors and output remain operational result data. Stdout and stderr are collected independently with no spill file, each retaining at most 64,000 bytes; `nextOffset` supplies the exact total byte count and `lossy` supplies the truncation fact.

The runtime does not reimplement the domain's pending tool-call, request-header, revision, or transition rules. It constructs the complete typed candidate and lets the existing Science invariant plus strict fold admit it at `Session.append()`. A rejected pre-start append removes only that operation's newly created unpublished run directory and rejects the request; it never spawns. This keeps transition semantics in `science-session` while the runtime owns external-fact ordering and rollback.

### Cancellation, disposal, and detached Sessions

The provider links the required caller signal, its fixed timeout, explicit handle cancellation, and service disposal through one first-cause controller. The timeout defaults to 120,000 ms and configuration may lower or raise it only within 1–600,000 ms. Subprocess grace is fixed at 3,000 ms. Cancellation after run publication calls `SubprocessHandle.terminate()` and still waits for `done` plus whole-tree exit before appending `cancelled`.

Service disposal first refuses new work, then cancels every owned probe and run, waits for every managed tree and terminal append, and only then returns. Dependency ordering keeps subprocess and sandbox providers alive until this Consumer has quiesced. Independent cleanup outcomes use `Promise.allSettled`; one failed target never starves another.

`session/disposed` is observe-only and cannot be awaited before the store detaches the Session. An unexpected detach therefore triggers cleanup but forbids any later append to that detached object or a same-ID successor. After the owned trees are quiescent, `done` rejects with `SESSION_NOT_LIVE` as specified in the runtime contract; cold replay derives `interrupted` from `session/end-seed` when the durable log contains an unmatched start. Normal Phase 3 teardown must cancel and await the runtime operation before detaching the Session. This note does not claim that arbitrary detach can always record `cancelled`.

### Conda observation and immutable prefix use

Profiles are a configured map from `ScienceEnvironmentProfileId` to at least one of `pythonPrefix` or `rPrefix`. The provider never invokes the `conda` CLI. It canonicalizes the configured prefix, requires a regular `conda-meta/history` inside that canonical tree, and uses fixed executable candidates only: `bin/python` and `bin/Rscript` on POSIX, `python.exe` and `Scripts/Rscript.exe` on Windows. The executable must be a regular executable whose canonical path remains inside the prefix. Current Windows sandbox enforcement is partial, so any observation requiring an executable probe and every Science run fail with `CONFINEMENT_UNAVAILABLE`; neither publishes its corresponding environment or run event until a full backend exists. A static missing or unusable interpreter may still publish the honest `invalid` observation described above because it starts no process.

Python version probes use `python -I -B -X utf8 --version`; runs use `python -I -B -u -X utf8 <code.py>`. `-I` intentionally ignores all `PYTHON*` environment entries, `-B` prevents bytecode writes, `-u` makes run output immediate, and `-X utf8` fixes source and text-I/O encoding. R version probes use `Rscript --vanilla --encoding=UTF-8 --version`; runs use `Rscript --vanilla --encoding=UTF-8 <code.R>`. `--vanilla` ignores user and site startup files, so no `R_ENVIRON_USER` or `R_PROFILE_USER` entry is supplied. On supported POSIX hosts both languages receive provider-fixed `LANG` and `LC_ALL`: `C.UTF-8` on Linux and `en_US.UTF-8` on Darwin, plus `TZ=UTC`. A second fixed direct-argv probe under the same dedicated `workspace-write` observation policy uses `python -I -B -X utf8 -c 'import sys;sys.stdout.buffer.write("dsh-科学-✓".encode("utf-8"))'` or `Rscript --vanilla --encoding=UTF-8 -e 'cat(enc2utf8("dsh-科学-✓"),sep="")'`. The binding is not `available` unless that probe exits zero and stdout exactly equals the UTF-8 bytes of `dsh-科学-✓` with empty stderr.

Version capture is at most 1,024 bytes per stream. It requires a lossless offset-zero read whose generic output fact is `utf8Validity === 'valid'`, then converts CRLF to LF, removes leading and trailing ASCII whitespace, rejects U+0000, and requires exactly one non-empty line from stdout, or from stderr only when stdout is empty. Any other shape is an invalid observation. Observation reads `fs.stat({ bigint: true })` identity for the executable, hashes exact `conda-meta/history` bytes, runs both probes with full enforcement in dedicated observation scratch, and then repeats the filesystem observations. One changed observation retries once; a second change records an invalid unstable observation instead of manufacturing a fingerprint.

`executableIdentity` is the UTF-8 string `stat-v1\0<platform>\0<dev>\0<ino>\0<mode>\0<size>\0<mtimeNs>\0<ctimeNs>`. Every numeric field is a base-10 integer without padding; `dev`, `ino`, `mode`, and `size` are non-negative, while timestamps retain their sign. All values come from one bigint stat. `bindingFingerprint` is `lowerhex(SHA-256(UTF-8("dsh-science-binding-v1\0" + language + "\0" + canonicalPrefix + "\0" + executable + "\0" + executableIdentity + "\0" + languageVersion + "\0" + condaHistorySha256)))`. It detects the captured identity changing; it is not a package lock or proof that every environment file is unchanged.

### Scratch layout and clean child environment

The provider resolves its root only through `resolveDshHome(config.dshHome)`. Before creating anything, it rejects a derived Science root that overlaps the canonical `/tmp` or `os.tmpdir()` root in either direction. The Session key remains `lowerhex(SHA-256(UTF-8("dsh-science-session-v1\0" + exactSessionId)))`. The safety marker `science/v1/owners/<session-key>.json` contains exactly `{ version: 1, key, sessionId }` at mode `0600`; its first creation uses exclusive `open('wx')`, exact UTF-8 JSON, file sync, and parent-directory sync. `science/v1/sessions/<session-key>/` and its `home/`, `state/`, `runs/`, and `probes/` directories are mode `0700`. Existing markers, directories, and source files are checked without following an unexpected symlink. A missing marker beside an existing Session root, malformed or mismatched marker, non-private managed file, or path escape fails closed.

Each run owns `runs/<run-id>/code.py` or `code.R`, `tmp/`, and `artifacts/`. Its cwd is that run directory. The source file and containing run directory are synced before the start event. Pre-start rollback may remove only the newly-created unpublished run directory; cleanup failures are aggregated with the initiating failure rather than hidden. Successful, failed, cancelled, resumed, Session-disposed, and service-disposed runs retain scratch. The provider never deletes or writes the configured Conda prefix. The owner marker is a collision guard, not a second event journal or projection database.

Each observation owns `probes/<observation-id>/home/` and `tmp/` plus the observation directory used as cwd. These are unpublished provider setup, not accepted user state. The provider removes that one observation directory only after every probe process is quiescent; a removal failure rejects the bind or preflight and prevents an environment or run event. It never removes `home/`, `state/`, an accepted run directory, or any other lifecycle's probe directory.

Science run processes set `environmentBase: 'empty'` and provide exactly `HOME`, `TMPDIR`, `PATH`, `SCIENCE_STATE_DIR`, `SCIENCE_ARTIFACT_DIR`, `LANG`, `LC_ALL`, and `TZ`, all fixed or provider-derived as specified above. On supported POSIX hosts `PATH` is exactly `<canonical-prefix>/bin:/usr/bin:/bin`; it is never ambient input. Python behavior is fixed by argv rather than ignored `PYTHON*` entries; R receives no user profile, environment-file, or library-path entry. Probes use the same empty base but only `HOME`, `TMPDIR`, `PATH`, `LANG`, `LC_ALL`, and `TZ`; `HOME`, `TMPDIR`, and cwd are inside the unique observation directory. R runs likewise point `TMPDIR` at the run's owned `tmp/` and reject before publication when its canonical path contains an ASCII space. No credential-shaped variable, proxy variable, `SSH_AUTH_SOCK`, user package path, ambient `DSH_*`, or caller-supplied entry is forwarded.

Run confinement is always `workspace-write` with `workspaceRoot` equal to the canonical Science Session root and `sessionId` equal to the exact Session ID. It never uses the project cwd or an agent-selected policy. Before wrapping, the provider uses the sandbox owner's `writableRoots(policy)` and a boundary-aware canonical path comparison to reject any configured prefix that overlaps a writable root in either direction. The generic sandbox also permits its documented platform temp roots; the runtime points `TMPDIR` at the owned run directory and accepts durable Science state or artifacts only from their owned directories. Confinement controls file writes, not reads, networking, syscalls, or scientific validity.

Probe confinement is also `workspace-write`, but its `workspaceRoot` is the unique observation directory rather than the full Session root. The same canonical overlap check covers every writable root returned for that exact policy, including generic platform temp roots. Probe write access exists only to satisfy interpreter startup requirements such as R's per-session temporary directory; it never authorizes the Conda prefix.

### File and test structure

Keep orchestration small. The folded package keeps `src/types.ts`, a thin `src/index.ts`, `src/invariant.ts`, and separate `config.ts`, `environment.ts`, `scratch.ts`, `execution.ts`, and `lifecycle.ts`. It exports `./invariant`; if no independently observable event/data relation exists, the installer gives a package-specific empty reason instead of exposing private lifecycle state for diagnostics. Every new Phase 2 production file stays at or below 400 physical lines, `index.ts` stays at or below 250, and each responsibility-focused spec stays at or below 600. Crossing a limit requires a responsibility extraction in the same commit, not a size exception.

Fake-prefix CI covers strict profile config, Python-only/R-only/shared and distinct prefixes, missing or escaping paths, stable and changing fingerprints, exact serialization and version normalization, owner-marker resume/fork/collision, exact modes, direct-argv paths with spaces and metacharacters, non-ASCII source/output, UTF-8 `valid`/`invalid` facts from retained bytes and `unknown` only when no byte slice exists, empty-base environment capture, fully enforced dedicated probe scratch and its cleanup, Science-root/temp-root and prefix/write-root overlap refusal, runner/denial classification, start-before-spawn and finish-after-tree-exit ordering, output byte boundaries, timeout/cancel/TERM-trap escalation, exact-Session concurrency, same-ID lifecycle quarantine before cleanup and safe reuse after quiescence, disposal quiescence, prefix before/after manifests, and strict cold replay. E2B recovered-byte reads report `valid` or `invalid`; they do not report `unknown` merely because the process world is remote. Python positively covers a space-containing non-temp Science root; R covers ordinary space-free scratch plus a fail-closed space-containing `TMPDIR` fixture. Fake prefixes and the isolated `DSH_HOME` used for an actual confined probe or run live under test-owned non-temp roots that do not overlap the sandbox temp roots or one another; a `/tmp` fake or `DSH_HOME` is only a negative overlap fixture. At least one Loader composition uses real `SessionStore`, Science invariants, local subprocess, local sandbox, the folded Runtime package, and a fake interpreter; mocks alone do not prove the runtime operations. Those tests do not complete the Science seam.

Real-machine acceptance is opt-in and receives explicit Python and R prefixes plus an isolated, test-owned non-temp `DSH_HOME`. It runs each language independently, verifies canonical executable/version/history identity, non-ASCII source/output, environment scrubbing, cwd and owned directories, success and cancellation/timeout, full confinement, prefix-write denial, and absence of provider-observable managed-tree processes or fixture-known descendants. It does not claim detection of a daemon that deliberately escapes the managed process group. A before/after recursive prefix manifest uses `lstat` without following symlinks and records relative path, type, symlink target, mode, size, mtime nanoseconds, ctime nanoseconds, and regular-file SHA-256; it deliberately excludes atime because observation itself may update it. Only an empty diff supports “prefix unchanged.” Python and R are each reported `PASS`, `FAIL`, or `NOT-RUN`. Fake CI does not prove real Conda, and source acceptance does not prove an installed application or release.

## Alternatives considered

**Spawn with `node:child_process` inside Science.** Rejected because it would duplicate managed-tree identity, TERM-to-KILL escalation, output bounds, host-exit fallback, and provider portability already owned by `ctx.subprocess`.

**Use `dsh-shell` or construct a shell command.** Rejected because interpreter, source, and paths are structured facts. A shell adds quoting and startup behavior without supplying any required product semantics.

**Implement Science as the Python backend of `ctx.codeRuntime`.** Rejected because Code Mode exposes host bindings and a portable SDK to one model program, while Science records Conda identity, Session provenance, files, and independent Python/R runs. Combining them would couple unrelated Consumers and durable semantics.

**Let tools append Science events around a low-level provider.** Rejected because every Consumer would have to reproduce the spawn-before-start prohibition, drift revision, exact-Session lease, quiescent finish, and detach behavior. The operation that observes or executes the fact owns its append.

**Keep the current scrubbed ambient environment.** Rejected because `PATH`, `HOME`, locale, proxies, and other non-credential variables still survive; “credential-shaped scrub” is not the promised explicit allowlist. Enumerating ambient tombstones in Science would race environment changes and duplicate platform key semantics, so the subprocess seam gains an explicit empty base.

**Use the Session project cwd as sandbox workspace.** Rejected because Science code may write only its owned scratch (plus the sandbox's declared temp roots), not the user's project. Project files may still be readable under the current threat model.

**Allow partial sandbox enforcement with a warning.** Rejected because an environment prefix outside the writable root is only read-only when the backend enforces the full file-effect promise. Phase 2 fails closed and reports the host unsupported.

**Create, clone, update, or repair Conda environments.** Rejected because package solving, approvals, locks, mutation rollback, and cleanup are a separate capability. Phase 2 observes and executes only configured existing prefixes.

**Delete scratch on success or disposal.** Rejected because explicit `state/` and run files are the MVP's cross-call state and diagnostic evidence. Cleanup owns processes and unpublished setup, not accepted user data.

**Treat every failed post-start append as `TERMINAL_COMMIT_FAILED`, including unexpected detach.** Rejected because a live Session whose append is rejected is still writable and needs an infrastructure failure, while a detached Session must not be written and recovers through replay-derived `interrupted`.

**Treat every failed post-start append as `SESSION_NOT_LIVE`.** Rejected because a fold, I/O, or invariant rejection on a still-live exact Session is not a liveness failure.

**Report E2B output as `utf8Validity: 'unknown'` because the SDK callbacks are text.** Rejected because the E2B provider already recovers the original command bytes from its base64 transport and therefore has the same byte slice the local collector uses.

**Leave Pwsh on its copied classifier while Bash and Science share the sandbox module.** Rejected because Bash and Pwsh already keep a call-for-call mirror. Migrating only Bash would recreate the drift that copy exists to prevent.

**Split a provider-neutral `dsh-science-runtime` from `dsh-science-runtime-local` in Phase 2 and let a test Consumer complete the seam.** Rejected because the [capability-seam rule](../../implemented/architecture/2026-06-13-capability-seams.md) forbids a preemptive split: one conceivable provider and no production Consumer stay one package. A test Consumer is not a production owner and cannot justify independent Definition/provider evolution.

**Pull Phase 3 tools into Phase 2 so the two-package split has a production Consumer.** Rejected because tools are model-facing, require the Science preset, and depend on the Core same-request compaction fix. That work remains Phase 3. The folded package keeps the operation API free of local-only types so those tools can inject `ctx.scienceRuntime` later.

## Acceptance criteria

- One package `@deepseek-ai/dsh-science-runtime` and its bilingual README implement the folded Service Definition plus local provider. There is no `dsh-science-runtime-local`, no production Consumer, no tool, preset, UI, or shipped profile entry. Exported service types contain no Host scratch path or other local-only module.
- The generic subprocess empty-environment, execution-world, and UTF-8-validity facts, plus shared sandbox classification, have definition/provider/Consumer migrations and focused tests; Bash, Pwsh, and other existing Consumers retain their prior behavior explicitly. E2B recovered-byte reads report `valid` or `invalid`.
- Runtime operations are the only owners of the three Phase 2 Science mutations, enforce exact live Session identity, reject concurrent same-Session work before side effects, and preserve different-Session concurrency.
- Every published run starts before requested-source spawn and finishes only after whole-tree quiescence. A post-start outcome either commits one matching terminal event, rejects `done` with `QUIESCENCE_UNPROVEN` or `TERMINAL_COMMIT_FAILED` on the still-live exact Session, or rejects with `SESSION_NOT_LIVE` after an unexpected detach.
- Environment observations and fingerprints follow the frozen algorithms, drift blocks spawn through a durable revision, and no operation invokes Conda or changes a configured prefix.
- Child processes receive the exact documented empty-base allowlist, use direct argv and owned cwd, and run only with full fixed confinement whose writable roots are owned scratch plus the generic sandbox temp roots, all disjoint from every environment prefix. Run events expose no Host scratch path, and no Science event exposes stdout or stderr text; environment events retain the absolute prefix and executable facts required by the Phase 1 schema.
- Cancellation, timeout, service disposal, spawn/runner failure, unexpected Session detach, and same-ID replacement quarantine have focused lifecycle tests with independent cleanup outcomes.
- Fake-prefix CI, an assembled Loader test, strict live/cold replay, prefix manifests, package typecheck/lint/coverage/build, documentation gates, and a fresh independent review pass at one clean exact local commit.
- Real Python and R acceptance remains a separate opt-in report with per-language `PASS`/`FAIL`/`NOT-RUN` and no inference from fake tests.
- The implementation is committed only to the standalone local repository unless the user separately authorizes a remote or upload.

## Risks

The main correctness risks are a Session detaching between process settlement and terminal append, an unstable prefix changing during observation, a sandbox runner failure being mistaken for program failure, and teardown releasing a lease before descendants exit. Exact-object checks at every commit, bounded stable observation, one shared classifier, and provider-observable quiescence address those boundaries without claiming arbitrary host races disappear.

The current sandbox is not a confidentiality boundary. A successful Science run may read project or user files and use the network, and generic platform temp roots remain writable. The preset and UI must disclose that limitation in later phases; Phase 2 tests must not describe full file-write enforcement as read or network isolation.

Environment fingerprints are observations, not reproducible-environment locks. Files outside `conda-meta/history` and the executable stat tuple can change without altering the fingerprint. Real acceptance therefore checks a stronger before/after manifest only for the “provider did not modify this prefix” claim and does not promote that manifest into the durable Session payload.

The generic empty-environment, execution-world, UTF-8-validity, and shared classification additions touch existing providers and Consumers. Pre-release policy permits the required-field migration, but typecheck and assembled tests must prove the migration did not silently change Bash, Pwsh, LSP, terminal, subagent, filesystem search, or E2B behavior.

Unexpected Session disposal cannot synchronously await runtime cleanup or guarantee a terminal append. The honest fallback is cleanup plus replay-derived `interrupted`, not writing to a detached log. Phase 3 must preserve the normal cancellation-before-detach order.
